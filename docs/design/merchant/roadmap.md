> 2026-08-12 基于 [store-settings.md](store-settings.md)（Shopline 设置 20 页实录调研）
> 筛选出适合本项目商家角色的功能，并定出 MVP 与扩展优先级。**前提**：本项目是
> B2B2C 平台型商城（一个 consumer 前台服务所有买家），不是 Shopline 那种独立站
> SaaS——所有取舍围绕「平台上的卖家」而非「独立站站长」。平台管理员的对偶路线见
> [platform/admin-roadmap.md](../platform/admin-roadmap.md)（admin 必补项与本文 P0
> 同批做，互为依赖）。写作当日现状：merchant
> 服务仅入驻 `Submit`/`Get` 可用（`ApproveApplication` 全表 UPDATE、`Reject`/
> `Activate` 是 panic 桩），merchant 前端仅路由骨架未接后端；此后实况以 `TODO.md` 为准。

## 一、取舍的判断标准（四条过滤器）

1. **平台型 vs 独立站**：只有独立站才有意义的功能一律不引进（域名绑定、结账定制、SaaS 套餐）。
2. **有没有服务落点**：能落进现有 10 服务或 TODO 第二阶段已规划的「结算服务」的优先。
3. **基础设施依赖**：依赖 Kafka / 通知中心的往后排（当前事件走进程内 EventBus，跨服务事件链不存在）。
4. **对卖货闭环的贡献**：入驻 → 建店 → 上品 → 定运费 → 接单发货 → 售后 → 看钱，闭环路径上的先做。

## 二、引进清单

| Shopline 功能（store-settings.md 章节） | 引进方式 | 落点 |
|---|---|---|
| §1 店铺资料（名称/Logo/简介/客服邮箱/营业状态） | 基本照搬；「休息」状态 = 全店商品前台不可购 | merchant「店铺信息管理」 |
| §1 商品种类 10 项枚举 | 直接照抄，用于入驻审核与类目推荐 | merchant 入驻表单 + admin 审核 |
| §4 地点（默认地点/多地点/发货优先级） | 分两期：P0 单默认地点（开店自动创建），P1 多地点 | inventory |
| §3 运费模板（通用运费 + 自定义分组） | 照搬骨架——marketplace 商家刚需（淘系运费模板同款） | order/checkout 计价 |
| §15 退货规则（结构化：时限/费用/范围） | 照搬三要素；书面政策富文本后置 | order 售后 |
| §16 操作日志（3 个月保留、按菜单/事件筛选） | 照搬表结构；商家自查与 admin 仲裁复用同一份数据 | merchant 或 platform 级审计表 |
| §10 通知场景清单 | **只抄场景枚举当需求清单**；实现分两期（P0 直发 / P1 模板中心） | 先进程内直发，后通知服务 |
| §8 员工与权限（店长/员工配额/合作伙伴） | 改造为 Casbin「店铺×成员×权限」两级模型——即 [platform/rbac.md](../platform/rbac.md) 里未落地的「商家子账号」 | 网关 RBAC 细化 |
| §13/14 账单结算 | **方向反转引进**：Shopline 是商家付平台钱，本项目是平台给商家分账；抄其账单列表/筛选/导出的信息结构 | TODO 第二阶段「结算服务」 |
| §9 文件库（分组/配额/选择器） | 改造为商品图片素材库 | MinIO 之上加薄业务层 |
| §19 品牌 | 裁剪：Logo/封面/简介并入店铺资料，不单独成页 | merchant |

## 三、不引进清单

| Shopline 功能 | 理由 |
|---|---|
| §11 域名绑定/密码保护 | 纯独立站前提，平台商城无此概念 |
| §2 收款服务商市场（44+90 家） | 平台统一收单（payment + 支付宝已接）；商家侧只需「结算账户绑定」一个字段，不需要渠道选择 |
| §12 结账设置大部分（表单字段三态/结账按钮/主题） | 结账是平台统一体验，不下放商家；「支付时锁定库存」inventory 预占已实现 |
| §13 SaaS 套餐/免佣额度（正向） | 不向商家卖软件；平台收入走佣金，归入结算服务 |
| §5 税费设置 | MVP 单一市场含税一口价；跨境再议 |
| §18 礼品卡 | 依赖货币锁定与营销体系，投入产出比低 |
| §7 客户账户设置（登录方式/社交登录） | user + casdoor 的平台级决策，商家无权配置；仅「自助退货」降维为退货规则的一个开关 |
| §6 语言 / §20 像素托管 | 商家内容翻译与第三方像素只在跨境/独立站场景有价值；behavior + tracker 已有第一方埋点 |

## 四、路线图

### P0 —— MVP

**验收口径：一个商家不求助平台就能走完「入驻→上架→接单→发货→退货→看到该结多少钱」。**

1. **修入驻闭环三个已知缺陷**（审批全表 UPDATE、`RejectApplication`/`ActivateMerchant` panic 桩）——不是新功能，是地基（TODO P0 区已列）。2026-08-13 起本条范围被 [onboarding.md](onboarding.md) 两段式入驻重构覆盖改写
2. 店铺资料 + 营业状态 + 商品种类枚举（§1 裁剪版）
3. 单默认地点：开店自动创建，对齐 inventory
4. 通用运费模板：按配送区域一档价格
5. 订单履约视角：新订单列表 / 发货填运单 / 状态流转（order 子订单模型已在，缺 merchant 视角 RPC 与前端接线；merchant app 的 `orders` 路由骨架正好用上）
6. 退货规则最小版：允不允许 + 时限
7. 新订单商家通知：固定模板直发邮件，**不建通知服务**
8. 审计简版：登录/审批/发货/改价四类事件入表

### P1 —— 经营补强（MVP 跑通后按此序）

1. **结算与账单**：分账记录、佣金计算、结算单列表 + 导出（「看到钱」从只读金额升级为可对账）
2. 员工与权限：邀请制员工 + 店铺级 Casbin 细粒度（= rbac.md 商家子账号）
3. 通知模板中心：Kafka 落地后按 §10 场景清单裁剪实现，替换 P0 直发
4. 多地点 + 发货优先顺序
5. 素材文件库
6. 政策富文本（退货/服务条款，带默认模板）
7. 小件：订单 ID 前缀、品牌素材位

### P2 —— 差异化/远期

元字段扩展商品属性（§17）→ 报表增强（merchant app 的 ECharts chunk 已拆好）→
本地配送/到店取货（同城模块，store-settings §3 自研备注）→
跨境三件套（多币种/税费/内容翻译）→ 客服邮箱域名验证与品牌邮件。
