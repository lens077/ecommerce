## 1. 基础设置 `/admin/settings/base`

**［自研备注］** 商家开店需绑定 IAM 账号。

### 商店基本资料
> 你的商店基本信息以及收信方式

| 字段 | 控件 | 说明 |
|---|---|---|
| 商店Logo | 图片上传 | 展示在店铺管理页面上，图片最大限制 10MB |
| 商店名称 | 文本框 | — |
| 商店联系人邮箱 | 文本框 | SHOPLINE（平台方）可通过此邮箱与商家联系。**［自研备注］** 系统需实现邮箱验证确保邮箱属于该联系人 |
| 客服邮箱 | 文本框 + 域名验证 | 客户可通过此邮箱联系商家。未验证时标注「邮箱域名未验证」，提供「验证客服邮箱域名」按钮，发验证邮件（提示条：已发送验证邮件至 xx，请点击邮件上的【确认】按钮以验证您的账户）。未配置品牌邮箱时发件人显示为 `StoreName<no-reply@mailshopline.com>`，可配置带域名的品牌邮箱以提升邮件到达率 |

### 商店经营信息
> 管理商店账单信息、商品种类以及经营所在地时区

| 字段 | 控件 | 选项/说明 |
|---|---|---|
| 账单地址 | 卡片 + 编辑弹窗 | 代表公司注册地址或个人常驻地址。账单地址决定账单税费；变更可能导致已绑信用卡扣费失败，系统会在后台处理已绑卡切换，失败需重新绑卡。空态显示「暂未填写 + 国家（示例值：中国）」 |
| 商品种类 | 下拉（单选） | **完整选项**：全类目 / 生活家居 / 流行衣饰 / 美妆保养 / 3C家电 / 户外运动 / 食品饮料 / 图书文具 / 亲子用品 / 宠物用品（空态「暂未填写」） |
| 经营所在地时区 | 下拉 | 示例值：(GMT+8) Asia/Shanghai |

### 结算货币
> 设置商店收款的结算货币。一旦订单成立不可修改，请慎重选择

| 字段 | 控件 | 说明 |
|---|---|---|
| 结算货币 | 只读 + 「修改货币」按钮 | 示例值：人民币元 (CNY)。一旦有订单成立或成功发放首张礼品卡后不可修改 |
| 自定义货币格式 | 开关 + 「编辑格式」按钮 | 未启用则使用系统默认货币格式 |

### 订单 ID 前缀
> 默认订单号从 1001 开始，可添加前缀创建 ID（如 "EN1001"）

- 展示当前效果（示例：1001, 1002, 1003...）+「编辑前缀」按钮

### 商店状态
> 正式运营前或需临时关闭前台时，可将商店设为「休息」状态；恢复运营改回「营业中」

- 下拉：营业中 / 休息（示例值：营业中）
- 页尾统一「更新」按钮提交整页表单

## 2. 收款 `/admin/settings/payments`

顶部推广位：开通 SHOPLINE Payments（信用卡手续费低至 2.4%+0.25 USD / 免交易佣金 / 支持国际主流币种收款），另有「已有帐号？绑定」入口。

### 更多收款设置
> 您可为客户提供更多支付选项，提升客户支付体验和支付成功率

三类收款方式：

| 分类 | 说明 | 入口 |
|---|---|---|
| 信用卡/借记卡收款 | 客户在结账页便可完成支付流程（内嵌收银台） | 「选择服务商」→ 服务商列表页 `/payments/search/thirdCreditCard` |
| 其他收款方式 | 客户需跳转至第三方页面完成支付，可同时启用多个服务商 | 「添加」→ 服务商列表页 `/payments/search/other` |
| 手动收款方式 | 客户通过此方式付款后，商家需手动将订单标记为已付款 | 「添加」下拉 → 自定义手动付款方式表单 `/payments/detail`；另预置「货到付款」（默认未启用，可一键启用） |

**［自研备注］** 手动收款方式适用于货到付款场景，按需启用。

其他能力：定制化设置（通过安装应用定制收款方式的展示：隐藏、排序、重命名）。

## 3. 发货与配送 `/admin/settings/delivery`

### 运费
> 设置店铺可配送的区域，以及顾客在结算时可选择的运费方案

| 项 | 说明 |
|---|---|
| 通用运费 | 针对所有商品（不包含自定义组中的商品）；显示「支持发往 N 个地区」 |
| 自定义分组方案 | 通过分组为指定商品配置物流运费方案，「添加分组」 |

### 本地配送
> 直接为本地客户配送订单

- 按地点逐一启用（示例：默认地点，未启用）；提示「客户下单时，使用地点默认顺序进行库存与配送管理」
- **［自研备注］** 扩展为同城模块或独立微服务时作为支持项

### 到店取货
> 允许本地客户自行取货

- 同样按地点逐一启用（示例：默认地点，未启用）

### 运输路由
> 在普通运输之外添加运输策略，客户结账时优先根据运输策略匹配运费方案

| 项 | 说明 |
|---|---|
| 路由设置 | 设置普通运输与运输策略的匹配和展示优先级 |
| 运输策略 | 通过分组为指定商品配置物流运费方案，「添加策略」 |

### 承运商账户
> 已有承运商账户可连接到商店，使用自己的费率

- 集成入口（实录）：Shipper迅朋物流（未安装/安装）、OneShip（未安装/安装）

### 包裹
> 用于运送产品的包裹尺寸和重量

- 已保存的包裹：使用包裹尺寸和重量，便于第三方承运商更准确计算费率；「添加包裹」

### 平台物流
> 全流程物流服务（平台自营物流推荐位）

- 示例渠道：OnePost 欧无忧（欧盟多国覆盖、支持代征代缴、参考时效 8-10 个工作日、支持普货/带电/特货）；获取报价走扫码/邮件

## 4. 地点 `/admin/settings/location`

> 管理用于存放库存、支持发货取货的位置信息

| 项 | 说明 |
|---|---|
| 可用地点 | 管理存放库存的位置、发货订单并销售产品；有数量配额（示例：已添加 1/15 个地点）；「添加地点」 |
| 默认地点 | 发货时和添加新商品时的默认地点；「更改默认地点」。开店时系统自动创建一个默认地点（示例值：东城区, 北京市, 中国） |
| 发货优先顺序 | 有新订单时按此地点优先级分配；「编辑发货顺序」 |

## 5. 税费 `/admin/settings/taxes`

**［自研备注］** 商家需咨询税务专家确定如何纳税。

### 收税地区
> 管理征收税费的地点；不确定纳税义务请咨询税务专家。可通过「创建配送区域」添加新的国家/地区

- 表格列：征收 / 国家/地区 / 操作（示例行：中国 — 收取消费税）

### 收税方式
> 设定店铺对商品/运费的收税方式

- 勾选项：**所有价格均含税** —— 产品价格将包含消费税与关税，对运费收取的税款包含在运输价格中
- 页尾「更新」按钮

## 6. 语言 `/admin/settings/lang`

> 添加想要翻译的语言，完成翻译语料编写，再把语言分配给对应市场，实现网站内容翻译

| 分节 | 内容 |
|---|---|
| 语言列表 | 「添加语言」；每种语言可「调整市场」。示例：简体中文（默认语言）、英语。经营多市场时需将语言分配给市场，保证对顾客可见 |
| 导入自定义翻译文案 | 表格批量导入：1. 导出语言物料 → 2. 填充翻译 → 3. 导入表格（导出/导入按钮） |
| 智能翻译文案 | 按场景选择应用（避免同时启用多个）：①多语言&多货币插件（一键 Google 翻译，适合机翻可满足的商家）②UGC多语言可视化翻译（可视化编辑器中翻译，适合精准翻译要求） |
| 语言选择器 | 开关「展示语言选择器」。需前往 店铺设计 > 页头或页尾组件 开启"显示语言选择器"；避免与多语言&多货币插件的选择器同时开启 |

## 7. 客户账户 `/admin/settings/customer`

### 登录链接
> 管理店铺内客户登录入口链接到的客户账户版本

- 单选：**经典客户账户**（基础个人信息管理与订单查看，适用 B2C）/ **新客户账户**（更多个人信息与订单管理，适用 B2B 和 B2C）
- 说明：客户仍可通过 URL 访问新客户账户
- 自助退货：开关（默认关）。允许客户通过账户自行申请和管理退货，配合「退货规则」自定义可退商品

### 新客户账户
> 管理新客户账户的登录注册设置

| 字段 | 控件 | 选项 |
|---|---|---|
| 主题配置 | 入口 | 自定义结账流程和新客户账户的主题与应用 |
| 登录验证方式 | 可拖拽排序 | 密码（默认）/ 验证码 |
| 登录后跳转页面 | 单选 | 客户账户个人信息页 / 客户账户订单页 / 登录前页面 |
| 其他设置 | 勾选 | 未注册客户可在登录页中激活账号（不发送激活邮件或激活奖励） |
| 登录链接 | 只读 | 格式：`https://<store>.myshopline.com/account/signIn` |

### 通用设置
> 经典与新客户账户同时生效

| 字段 | 控件 | 选项/说明 |
|---|---|---|
| 通过社交媒体登录 | 连接列表 | Facebook 登录 / Google 登录（未连接→连接）+「更多社交媒体登录」；适用账户类型：经典客户账户、新客户账户 |
| 登录/注册账号类型 | 勾选 | 邮箱 / 手机号（勾手机号需提前开通「我的短信」应用并保证短信包余量充足） |
| 营销内容订阅 | 开关 + 勾选 | 客户注册时可订阅营销内容；可设置订阅选项是否默认勾选（按所在国法律）；可发二次确认邮件。当前仅支持 OS 2.0 主题 |
| 安全验证 | 勾选 | ①注册时发送邮件/短信验证信，必须验证才能完成注册 ②有风险账号注册/登录时开启图形验证 |
| 其他设置 | 勾选 | 允许客户注销账户 |

## 8. 管理员和权限 `/admin/settings/adminpermission`

### 权限
> 管理员工可在商店中查看的内容或执行的操作

| 项 | 说明 |
|---|---|
| 店长账号 | 显示店长邮箱；支持「换店长」 |
| 员工 | 邀请制，有配额（示例：已邀请 0 个，剩余可邀请 5 个）；「添加员工」 |
| 合作伙伴 | 允许开发者、代运营、设计师进入店铺辅助经营；不计入员工数量限制 |

### 安全
| 项 | 说明 |
|---|---|
| 双重验证 | 开关「强制开启双重验证」：所有用户（含店长）必须密码+邮箱验证码登录后台 |
| 页面水印 | 开关「开启页面水印」（推荐开启）：所有用户进入后台显示水印，内容为当前登录账号信息，防信息外泄 |

## 10. 通知 `/admin/settings/notice`

> 触发式消息模板中心。试用套餐仅能使用默认模版，自定义模版需升级套餐。

### 客户邮件通知
> 指定条件下系统自动向客户发送邮件，可自定义每个场景的邮件内容；内容需遵守邮件运营商规则

按场景分组（每个场景一个可自定义模板，实录全量）：

| 分组 | 场景 |
|---|---|
| 订单 | 订单确认（COD 订单创建和在线订单支付成功时）/ 订单编辑 / 发货更新（全部发货时）/ 配送更新 / 订单取消 / 订单退款 / 弃单召回（含高级设置，适用于未归档弃单）/ 草稿单账单（手动发）/ 订单账单（未付款时手动发）/ 退款成功 / 账单逾期（含发送设置） |
| 本地配送 | 正在配送 / 已送达 / 配送未成功 |
| 到店取货 | 准备取货（POS 或后台手动发）/ 已取货 |
| 退货 | 订单退货 / 客户请求退货 / 客户请求退货被批准 / 客户请求退货被拒绝 / 订单已退货 |
| 物流更新 | 正在派送（运单号状态变化触发）/ 已送达 |
| 客户 | 客户邀请 / 注册成功 / 激活成功（邀请未设优惠）/ 激活优惠（邀请设了优惠，含折扣码）/ 重置密码 / 联系客户（默认模板）/ B2B访问电子邮件（客户被加入公司时）/ B2B公司账号申请 / 购买礼品卡 / 接受礼品卡（向受赠人） |
| 客户订阅 | 订阅成功 / 取消订阅 / 客户营销确认（邮件双重选择加入时，含营销订阅设置） |

### 商家邮件通知
> 店铺收到新订单等事件时向员工发邮件；可自定义模板与接收员工邮箱（「模板」「员工邮箱设置」）

- 场景：新订单 / 客户请求退货 / 订单退款失败

## 11. 域名 `/admin/settings/domain`

> 主域名为 `<store>.myshopline.com` 时自动开启密码保护；成功绑定自定义域名后可关闭

| 项 | 说明 |

### Shopify 增量调研：礼品卡经营闭环

> 来源：[《如何为在线业务创建礼品卡（2026）》](https://www.shopify.com/zh/blog/sell-gift-cards)，
> Shopify Staff，2026-07-28。该文是经营指南，不是本项目的需求或法律依据；下文只提炼
> 可转化为产品设计的能力，并用 **［自研备注］** 标出本项目决策。

Shopify 将礼品卡定义为商家预先收款、客户以后用余额消费的预付凭证，并区分两类：

| 类型 | 兑换范围 | 对本项目的意义 |
|---|---|---|
| 封闭式礼品卡（closed-loop） | 仅在发卡商店购买和兑换 | **［自研备注］** 若未来引进，只考虑这一类；礼品卡必须绑定发卡商家，不能默认跨店使用 |
| 开放式礼品卡（open-loop） | 由卡组织或第三方礼品卡网络管理，可在参与商户使用 | **［自研备注］** 属于支付/预付卡合规与外部卡网络范畴，不作为商家设置能力自研 |

数字卡与实体卡共用同一余额和兑换语义，差别只在载体与交付：数字卡通过邮件或短信即时发送，
实体卡印制代码或条形码并可在 POS 扫码。Shopify 的全渠道做法允许实体卡在线输入代码、数字卡在线下
POS 核销。**［自研备注］** 本项目当前没有 POS，未来若重评礼品卡，第一阶段只做数字卡；不要为了
「实体卡」提前引入制卡、扫码和门店终端边界。

#### 从创建到核销的能力链

| 环节 | Shopify 文章中的能力 | **［自研备注］** 转化为本项目约束 |
|---|---|---|
| 创建商品 | 标题、描述、媒体、面额、SEO 预览、销售渠道、发布日期、商品分类与标签 | 礼品卡可以复用商品展示和上下架能力，但面额 SKU 不对应实物库存；单卡上限应按币种和地区配置，不硬编码文章示例值 |
| 购买 | 买家把礼品卡加入购物车，填写收件人、留言、邮件/短信和发送时间 | 购买者与受赠人是两个主体；受赠人未注册也应能收卡，兑换时再绑定或校验身份 |
| 发放 | 支付成功后生成卡并即时或预约发送 | 只有支付最终成功才能激活；高风险订单不得自动发放。对应本文 §12「仅自动对订单的礼品卡进行发货」 |
| 通知 | 品牌化邮件包含代码、余额、兑换说明、行动入口和客服联系方式 | 复用本文 §10「购买礼品卡/接受礼品卡」通知场景；日志与客服界面只能展示掩码代码，不能在后台列表明文泄露完整凭证 |
| 兑换 | 结账时输入代码，支持部分核销并保留剩余余额 | 礼品卡是支付工具，不是折扣码；应在优惠计算完成后抵扣应付金额，并记录每次余额变动而不是只改一个余额字段 |
| 管理 | 查看客户、购买时间、订单、当前余额，单张或批量设置有效期 | 余额台账必须可审计；过期策略按发卡时适用规则固化，后续改设置不能追溯缩短已售卡有效期 |
| 分析 | 销售额、未使用余额、核销率、平均超额消费、新客获取、线上/门店渠道表现 | 销售礼品卡先形成合同负债，不应立即当作商品收入；核销时再进入商家结算与收入确认流程 |

最小状态流应覆盖：

```text
草稿 -> 待付款 -> 已激活 -> 部分核销 -> 已用尽
                     |            |
                     +-> 已冻结 <-+
                     +-> 已过期
                     +-> 已作废
```

- 「冻结」用于欺诈调查、拒付或账号风险，解冻后回到冻结前状态。
- 「作废」是人工纠错或退款后的终态，不等于余额为零；每次状态变化都要记录操作者、原因和时间。
- 购买订单取消、支付退款、拒付、礼品卡支付订单退款时，余额回退和资金责任需要独立规则，不能复用普通商品的库存回补逻辑。

#### 风控与合规护栏

Shopify 文章建议限制单笔购买张数和总金额、延迟发放高面额卡、在订单处理前做欺诈检测，
并把「多张、多面额、拆分支付」视为需人工关注的信号。对应到系统能力：

1. 店铺设置只允许商家在平台上限内收紧单卡面额、单笔张数与单日购买总额，不能自行放宽平台风控上限。
2. 风险命中时进入「待审核」，暂停生成可兑换代码和发送通知；审核操作写入 §16 操作日志。
3. 完整卡号按支付凭证保护：生成时使用密码学安全随机数，存储不可逆摘要，查询、日志、埋点和客服页面只返回掩码。
4. 过期、休眠费、退款和未核销余额的处置因国家/地区而异。Shopify 文中所举美国「激活后至少五年有效」仅是地区示例，不能作为全局默认；上线国家必须经过法务与财务确认。
5. 礼品卡折扣或「购买金额小于可用面值」会额外扩大平台资金敞口，必须与营销预算、退款和拒付规则一起评审，不能当作普通商品划线价。

#### 本项目取舍

**［自研备注］** 本节补充调研不改变 [roadmap.md](roadmap.md) 的当前结论：礼品卡不进入
P0/P1，原因仍是它同时依赖货币锁定、结账抵扣、通知、反欺诈、合同负债台账和商家结算。
未来只有在这些前置能力稳定后才重评；若重评，最小范围是「单商家、单币种、封闭式数字礼品卡」，
并明确多商家购物车中只能抵扣发卡商家的子订单，不能抵扣平台运费、税费或其他商家的应付金额。
