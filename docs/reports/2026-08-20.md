## 接手操作要点（干活前 60 秒过一遍）

1. **触发 CI/部署 = 打 tag**：`git tag <X.Y.Z> && git push github <X.Y.Z>`——必须推
   `github` 远端（origin 是 GitLab 无 Actions）；修复→Z、功能→Y、破坏性→X；tag 不复用。
   推 main 只跑文档门禁，不构建。
2. **发布后 github 会多一个 `[skip ci]` 回写提交**：下次动手前 `git fetch github` 并
   merge（不 rebase 不 force）。
3. **换/停任何基础设施前**：消费者三查——`config.entry` SQL 扫描 +
   `config-center-bootstrap` Secret + 网关 Config Center 四键；并先确认 CC pod `READY 1/1`
   （老 pod 靠内存配置活着，会掩盖 CC 已死）。
4. **OpenBao 每次 pod 重启是密封态**：`components/openbao/examples/unseal.sh`。
5. **Dragonfly 密码与 redis 组件同值**（creds/dragonfly-password）；客户端连
   `rediss://dragonfly.dragonfly.svc:6379`，严格 CA 校验（trust-manager 的
   `cm/global-root-ca` 各 ns 都有）。
6. **回滚缓存**：`kubectl -n redis scale sts redis --replicas=1` + 三处 host 换回（分钟级）。
7. **内环开发**：mirrord 已定为默认（PoC 验收单=对抗第 3 轮 R3-B），Okteto 保留特例
   且必须走 devwindow 开关。
8. **Mac 别睡眠**：跑长任务前 `caffeinate -dimsu` 或 pmset；控制面翻覆多半是这个。
