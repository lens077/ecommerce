## P0 · 2026-08-29 控制面雪崩的遗留项

> 完整故障链：node101 内存耗尽（可用 140 MB）→ kswapd 狂转、page cache 以 ~1.8 GB/s 反复读盘、
> iowait 40%+、load 41.93（4 核）→ apiserver 单次 lease 查询 7.43 s，超过 5 s 租约超时 →
> scheduler / controller-manager 反复丢主崩溃 → **EndpointSlice 控制器停摆** + 无法调度 →
> OpenEBS CSI 插件铺不到 node102/103 → Consul PVC 挂不上；
> dragonfly 换 IP 后 **CiliumEndpointSlice 卡在旧 IP**，agent 把新 IP 判成 `world` 身份 → CNP 拒绝。

- [ ] **`KCM_TERMINATED_POD_GC_THRESHOLD=100` 阈值设计有缺陷**：本次积压了
      **97 个** `NodeShutdown` 僵尸 Pod，恰好卡在阈值之下，GC **永远不会触发**；
      而 controller-manager 本身又在崩溃，更无从回收。这些 Pod 持续消耗 etcd 与
      apiserver list/watch 带宽。修法：下调阈值，或改用基于**时间**的回收，
      并对「Failed Pod 数 > N」告警。约定见
      [`context/team/node-graceful-shutdown.md`](../../context/team/node-graceful-shutdown.md)。

- [ ] **node102 / node103 内存仍是 3.3 GB**：node101 已扩容至 6.4 GB，另两台未动。
      当前 15 个业务 Deployment 挤在 3 台小节点上，**N+1 容量目标无法成立**。
      需要明确：要么继续扩容，要么按真实容量削减常驻平台组件（见下条）。

- [ ] **平台组件相对硬件严重超配**：29 个 namespace 跑着 Cilium / Kyverno / ArgoCD / KEDA /
      VPA / Tetragon / OpenEBS / cert-manager / external-secrets / OpenBao / OpenFGA /
      NATS×3 / Meilisearch / Dragonfly / Consul / Vector / OTel……单 kube-apiserver 就占 1076 MB。
      需要一次**平台组件必要性审计**：KEDA（0 个 ScaledObject）、Argo Rollouts（0 个 Rollout）、
      Kyverno（0 条生效策略）三者当前**装了但零使用**，却持续占用内存与 etcd。

- [ ] **CiliumEndpointSlice 陈旧无自愈**：CES 卡在旧 Pod IP 时，agent 会把新 IP 判成 `world`，
      CNP 静默拒绝，表现为「策略明明放行却不通」。本次靠手工删除 CES 触发重建才恢复。
      需要：对「CiliumEndpoint 与 CES 的 IP 不一致」加巡检或告警——
      这类故障**没有任何现成告警会报**。

## P2 · TLS 收敛

> 目标态是「每个基础设施都 TLS」。按**代价从低到高**排序。
> ⚠️ 验收一律以**实测握手/协议响应**为准，不以 listener 配置表面状态为准。

- [ ] **12 条基础设施 HTTPRoute 从 http listener 迁到 https**（一行改动一批，收益最大）：
      grafana / vm / kibana / es / kafka-ui(×2) / minio-api / minio-ui / jaeger-ui /
      jaeger-http / seata / consul-ui / argocd-server 目前全挂 `sectionName: http`（80 明文），
      改挂 `https` 即获得网关终止的 TLS（泛域名证书 `global-default-tls` 已覆盖 `*.dev.test`）。
      **验收**：改前 `https://<host>` 返回 404、改后返回与 http 相同的业务响应；
      同时决定 80 listener 是保留（做 301）还是关闭。

- [ ] **公网明文端点**（优先级高于所有集群内明文）：casdoor `apikv.com:8000`
      承载 OAuth code/token 交换，**走公网 http**（2026-08-29 node1 实测确认 8000 仍为明文，
