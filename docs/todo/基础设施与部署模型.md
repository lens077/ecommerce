### 端到端业务链路验证〔实测 2026-08-29〕

雪崩恢复后做过一次真实链路验证——**不是只看状态码，而是核对返回内容**：

| 检查 | 结果 |
|---|---|
| `https://gateway.dev.test/healthz` | 200，50ms |
| `https://shop.dev.test/zh/product/iphone-15-pro` | 200，11.5KB，SSR 注水含真实库中数据 |
| 直连网关 RPC `product.v1.ProductService/GetProductDetail` | 200，返回「雅诗兰黛小棕瓶精华」CNY 650/1150 |
| SPA 站点根 `https://shop.dev.test/` | 200，标题「灯市」 |

SSR payload 实含 `spuName:"Apple iPhone 15 Pro"`、两个 SKU（CNY 8999/10999）、
`commonSpecs`，且 `status:"success"`、`error:null`、`fetchFailureCount:0`。
即完整走通 **浏览器 → Cilium Gateway(.121) → consumer-next SSR → 匿名 transport →
control-tower 网关 → product 服务 → node3 Pigsty PostgreSQL**；直连 RPC 是独立路径，同样通。

复验命令：

```bash
curl -sSk https://gateway.dev.test/healthz -o /dev/null -w '%{http_code}\n'
curl -sSk https://shop.dev.test/zh/product/iphone-15-pro | grep -o 'Apple iPhone 15 Pro'
curl -sSk -X POST https://gateway.dev.test/product.v1.ProductService/GetProductDetail \
  -H 'Content-Type: application/json' -d '{"spuCode":"estee-lauder-anr"}'
```

⚠️ 两个已知非故障现象，别误判：

- **`/zh` 返回 404 是正确行为**——consumer-next 只实现了商品详情页，**没有 index 页**
  （`app/[lang]/` 下只有 `product/[spuCode]/page.tsx` 与 `not-found.tsx`），
  扩页受阻于 `ListProducts` RPC 未实现。
- **验收别用 `grep -c` 数命中**——SSR 注水 payload 挤在同一行，`grep -c` 数的是
  匹配**行数**不是次数，会得到「1 处命中」的假象并误判成假成功。本次实测差点因此
  得出反向结论。
