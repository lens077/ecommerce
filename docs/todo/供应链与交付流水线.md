## CI 触发纪律（2026-08-29 变更）

**GitHub Actions 预算超支后，平台会直接拒绝运行。** 因此所有 GitHub workflow 已收敛为
**仅发布 tag 触发**（裸 semver `X.Y.Z`）：

| workflow | 触发 |
|---|---|
| `backend.yml` | tag `X.Y.Z` + 手动 |
| `context-gate.yml` | tag `X.Y.Z` + 手动（原每 PR/push） |
| `deploy-consistency.yml` | tag `X.Y.Z` + 手动（原 push main + PR） |
| `supply-chain-pr.yml` | tag `X.Y.Z` + 手动（原 PR） |
| `frontend.yml` | **仅手动**（原每日 cron，最贵的常驻消耗） |
| `service-ci.yml` | `workflow_call`（被调用，不自触发） |

⚠️ **per-push 覆盖没有丢**：`.gitlab-ci.yml` 的同名 `context-gate` job 仍挂在
`$CI_COMMIT_BRANCH` 与 MR 上，而 origin 就是 GitLab。本地
`scripts/verify-quick.sh` / `scripts/verify-context.sh` 仍是提交前锚点。

理由与验证方法见
[`evolution-log.md`](../../context/harness-framework/evolution-log.md) 2026-08-29 条目。
