## 纪律

1. **任何待办项的新增、勾选、关闭、改优先级，都必须同步回 `TODO.md`** 的分类索引
   （至少更新该分类的未完成计数与最高优先级项）。两处不一致时**以 `TODO.md` 为准**。
2. 分类文件里只写**待办**。已完成的验收证据长文归
   [`docs/progress-archive/`](../progress-archive/)（不可变历史，非并行真相源），
   调研报告归 [`docs/reports/`](../reports/)。
3. 目标态描述**不在这里复述**——每份文件顶部只放 TECH.md 对应章节的摘要与链接。
   选型冲突一律以 `docs/TECH.md` 为准。
4. 跨分类的条目放在**最主要**的那一类，其余分类用一行交叉引用，不复制正文。

## 优先级口径

| 级别 | 含义 |
|---|---|
| **P0** | 正确性、资金/库存安全、越权、数据泄露，或**阻断其他所有工作**的故障 |
| **P1** | 交付闭环所必需：功能打通、可观测、可运维 |
| **P2** | 演进与优化，可被真实需求或容量证据触发后再排期 |

⚠️ P0 的判据是**后果**不是紧迫感。「调用会成功但结果是错的」「任何登录用户都能越权」
一律 P0——它们不会在联调时暴露，只在上量后以超卖、丢单、数据泄露的形式爆发。
