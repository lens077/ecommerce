## C'. 结果登记（captain 于 2026-08-20 回填；全文见团队任务 t3/t4 output（[`团队存档/team.json`](团队存档/team.json)））

### C'.1 逐题裁决

**T1 开发机 ↔ 集群双向通信（收敛一致，直接采纳）**
- 集群→Mac：**mirrord**（默认 mirror；steal 限 dev 环境 + 限时，禁碰 prod 流量）。论据合并：进程级介入不创建/不缩容集群对象→与 ArgoCD selfHeal 零冲突，根治 devwindow 手工开关；拦截点在目标 pod，与发现机制无关——Consul 退役迁移期不用换工具；集群与 Mac 同为 arm64，本地编译即集群产物。
- Mac→集群：**零新件**——常规调用走网关 VIP（与生产同路径；实测已有 17 个 Cilium LB VIP + `*.dev.test` 约定），单服务调试直连其 VIP（**仅限 dev**：直连绕网关鉴权），私有 RPC 兜底 `port-forward`。
- 两人一致否决：手工 EndpointSlice 指 Mac IP（「不在 Git 的手工集群状态」本仓已两次买单，stale IP 即静默黑洞）、CoreDNS 静态映射、为此保留 Consul、Telepresence（Manager/VPN/DNS 过重）。
- **mirrord 孤证裁决（双方一致）**：部分支持——第 1 轮主稿「mirrord 替 Okteto」改为「**mirrord 为默认内环工具，Okteto 降级保留**」：uid 1000/Secret 0400 文件权限/镜像内行为等「集群身份」场景 mirrord 原理上不复现，Okteto 已有端到端实测与七条清单沉淀，删除是负资产。PoC 验收项：mirrord × Cilium KPR/h2c 的 steal 兼容性。

**T2 19.5G 预算表（合成两案）**
- 前置（采 claude2，唯一有实锤数字）：**先杀残留回收 ≈1.4Gi**——seata 613Mi（backend 零引用）、strimzi 246Mi、Loki 187Mi（切换后）、cilium-test 102Mi、集群内 minio 91Mi、tempo 35Mi、dragonfly 残留、Consul（退役后）。
- 结构（采 codex 表 + claude2 校准法）：limits=1.5×requests（CH/网关 2×）；CNPG×2 反亲和 N1/N2、NATS×3 每节点、Meili@N3、CH@N3 或 N1（与 PG 主错开，`max_server_memory` 2G 顶格）、观测柱分居 N1/N2、OpenFGA×2、**Tetragon 首批不上（两人一致缓）**；requests 以 VPA/实测校准（现状教训：requests 95% vs 实用 62%）。
- 结论区间：requests 合计 ≈12.9–13.3Gi / 19.5Gi，**余量 22–34% ≥20% ✓**（两案殊途同归）。
- 合并砍序：①残留清单 ②Tetragon（已缓）③Kyverno 降 audit-only ④Jaeger 降采样/保留期 ⑤CH limit 降档（埋点可断代重放）⑥KEDA 缓（HPA 顶）⑦OpenFGA 2→1 ⑧Spegel/Chaos/Numaflow 永远排在备份/PG/网关之前被砍。不可砍共识：CNPG×2、VL+Vector、VM、网关+10 服务、redis、cert-manager、ArgoCD、备份组件。

**T3 两台线上 docker 机（一处实质分歧，裁决归 claude2）**
- 共识：**4c4G = SeaweedFS 单机 S3 异地备份靶**（CNPG-Barman + Velero 推送目标；客户端 age 加密后密文着陆；替已归档 MinIO）；**2c2G = 域外哨兵**（拨测网关 VIP/集群健康、独立告警出口；容量允许时做备份第二副本）；两台**均不承载业务**；RPO=WAL 归档 5min/最后一段 WAL + 夜间 Velero；推送型备份 + 归档年龄监控 + 哨兵与集群互拨 + 每周恢复演练；可选冷云第三副本凑 3-2-1。
- **分歧：casdoor**。codex 主张留外+备份；claude2 主张收编进集群。**裁决：采 claude2（收编）**——两条实锤压倒：①casdoor 正以公网明文 http 承载 OAuth code/token（TODO L42 实测⑥）②IdP 坐在 <50% 可用性箱上=全站登录单点；且「云箱不载业务」本是 codex 自己的原则，收编与其方向一致。附执行前提：收编后 IdP 可用性=集群可用性（Mac 停机则登录不可用——与业务同域，可接受）；排期放 TLS 整改窗口；DB 进 pg-main（Database CR）。

**T5 OpenFGA 落地形态（收敛一致，微差合成）**
- 部署：2 副本反亲和 N1/N2，128-200/256Mi。
- store：**pg-main 内 CNPG `Database` CR 建独立 `openfga` 库**+独立 role+独立连接池上限（防 check 流量抢业务池；模式已由 ecommerce 库验证）。
- 边界条款：网关 Casbin 管「JWT/角色×路由」粗闸（进程内 0 跳，不动）；OpenFGA 管「主体×资源实例×关系」（商家-店铺-商品-操作员/订单），只在服务内调用，**禁止网关热路径远程 check**；首接域=merchant，影子双跑后强制。
- 延迟预算（合成）：check p95≤15ms 验收线；p99 25ms 目标、50ms 熔断线；列表用 ListObjects/BatchCheck 预取；服务端 check-cache 开 + 模型版本化缓存 + 撤权事件清缓存；写路径永远实查。
- 失败分级（条款化，采 claude2 原则）：**降级只准缩小授权集，不准扩大**——写/资金/管理 fail-close；读单资源 owner==subject 本地短路、其余 fail-close；列表/推荐 fail-open 降「仅本人+公开」；公开读 fail-open。
