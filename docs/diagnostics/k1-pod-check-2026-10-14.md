# 第三轮 · gorse 故障修复记录（05:05 GMT+8）

## 根因链（全链路实证）

```
gorse (node2, Docker) 启动即崩
  └─ dial pg.apikv.com:52288 (→ node1) connection refused
       └─ node1 上 52288 无监听、无 NAT 规则
            └─ node1 的 postgres 容器（映射 52288:5432，卷 postgres_postgres_data）
                于约 1 小时前被干净停止（Exited 0）→ 端口映射随容器消失
  └─ 修好 pg 后，下一阻塞：dial redis.apikv.com:61246 (→node1) refused
       └─ node1 的 redis 容器（映射 61246:6379，卷 redis_data）同批被停止
```

同批受影响的还有 node1 的 `casdoor`（连 172.18.0.1:52288，panic 崩溃循环）与 node2 的 `minio`（Exited 0）。

## 修复动作（均已执行并验证）

| # | 动作 | 结果 |
|---|---|---|
| 1 | `ssh node1 docker start postgres` | 52288 恢复监听，node2→pg TCP OK |
| 2 | `ssh node1 docker start redis` | 61246 恢复监听 |
| 3 | 等待 gorse 重启策略自动重试（~60s 周期） | gorse-gorse-1 **Up**，`GET /api/health/ready status_code:200` 持续 |
| 4 | 公网链路验证 | `https://gorse.apikv.com/api/health/ready` → **200** |
| 5 | k1 侧验证 | behavior Pod **1/1 Running**（未增加重启，靠 readiness 自愈）；healthz `{"gorse":"ok","postgres":"ok","redis":"ok"}` |

**附带修复**：node1 `casdoor` 容器同根因自愈（Up About a minute），merchant 的 casdoor 依赖恢复。

## 关键拓扑事实（沉淀）

- `gorse.apikv.com` / `casdoor.apikv.com` / `pg.apikv.com` / `redis.apikv.com` 均解析到 **node1**（Pangolin + Traefik + WAF 栈）
- gorse 与 minio(silo) 跑在 **node2**（Docker，SSH 见 ~/.ssh/config）；gorse 的数据库与缓存是 **node1 的 docker postgres(52288)/redis(61246)**，不是 k1 集群内的 PG/Dragonfly
- SSH 别名：`node1` / `node2`（见 ~/.ssh/config）
