# E3 执行策略与消费边界

## 三档规模

| 档 | 判定 | 最小执行 |
|---|---|---|
| L1 | 单文件、无契约变化、可回滚 | 直接改；跑相关门禁；一句话汇报 |
| L2 | 跨文件、接口或数据形态变化 | 先写清楚改动点与回滚方式；跑 `harness check`；给 diff 摘要 |
| L3 | 动门禁、真相源、CI、发布链路 | 先出方案再动手；必须补 canary 探针；全量复跑并给结果 |

升级原则：拿不准时按更高一档处理，但不要为了「保险」把 L1 做成 L3——过度流程和没有流程一样会让门禁失效。

## 消费边界（给 subagent 与并行任务的约束）

- 单轮 subagent 数量上限由主会话控制；派单前先说明数量与理由。
- subagent 拿不到用户授权上下文，**不得**执行 commit / push / 部署 / 删除。
- subagent 的产出必须能被主会话复核：给文件路径、命令与结果，不给「已完成」四个字。
- 只读调查与写代码分开派单；写代码的 subagent 必须被告知验证命令。
