# 决策：TODO.md 只记 TODO 项，干净由内容形态门禁守而非字节预算

## 问题

[2026-08-30 的决策](2026-08-30-todo-md-sole-progress-source.md)把 `TODO.md` 定为进度唯一真相源，配了
96000 B 的字节预算。预算守住了「太大」，没守住「装错东西」：2026-09-16 量到它 82 KB 仍在预算内、门禁绿，
但「全局优先级视图」堆了 25 条 `2026-xx-xx 做了什么` 的流水账（首段单行 1441 字节），「现状对照」50 KB
里 67 条带日期证据行、单个表格单元格长到 2000+ 字节（一次事故的完整取证）。CI 的 `backend.yml` 也在
每次发版往它末尾追加一行。硬规则 3「提交前先更新 TODO.md」把每次提交都变成往这份文件里写点什么的动机，
文件自己的纪律 3「证据长文归档」没有门禁、没被执行。

后果是每个提交回合把整个月的操作记录整份读进上下文——Structured Note-Taking 退化成信息堆砌。

## 决策

**定义。** `TODO.md` 只回答四件事：有哪些待办、优先级、当前状态（✅🟡🔴⬜）、明细在哪。
每一行都是「待办 + 状态」或指向它们的索引。做了什么、实测数字、处置过程、会话记录不进本文件：
按月追加到 `docs/progress-archive/YYYY-MM-progress-log.md`（不可变），CI 发版行由流水线写进
`docs/progress-archive/ci-releases.md`。

**硬规则 3。** 从「提交前先更新 TODO.md」改为「提交前先判断改动是否涉及 TODO 项：涉及才更新
（完成 / 部分完成 / 改目标 / 删除），不涉及不动」。全文在 AGENTS.md，`git-commit.md` 与 runbook §6 同步。

**门禁。** `scripts/verify-context.sh` 新增 `[TODO-CLEAN]`（围栏外）：以日期开头的行（允许前置 `> ` / `- ` / `**`）
即红——流水账的形态；单行 > 600 字节即红——证据长文的形态（表格行即单元格容器）。96000 B 预算保留为兜底。
canary 加 `todo-dated` / `todo-long` 两个红探针与 `todo-fenced-ok` 假阳性守卫。

**存量。** 2026-09-16 的流水账、现状对照证据、阶段推进已完成项证据、CI 发版行整体逐字归档进
`docs/progress-archive/2026-09-16-todo-status-snapshot.md`（相对链接加 `../../` 前缀，正文不改）；
现状对照压成「状态 + 一句缺口 + 链接」的领域状态表。

## 考虑过的替代方案

- **把字节预算反向棘轮压到 40 KB** — 用户否决：问题不是大小是内容。一份 30 KB 的 changelog 同样错，
  一份 90 KB 的纯待办清单也可以对。字节预算只做兜底。
- **禁止 `〔实测` 字样进 TODO.md** — 与 `[LIVE-FACT]` 冲突：状态表里保留的运行时数字按规矩必须带实测日期。
  改为拦「行首日期」与「超长行」两种形态，与 LIVE-FACT 正交。
- **把「现状对照」整节搬到独立的 `docs/STATUS.md` 活维护** — 多一个真相源；且它一旦活维护就会重新长出证据。
  选择压成状态表留在 TODO.md（状态本来就是待办的一部分），证据归档不可变。
- **让 CI 继续往 TODO.md 追加发版行** — 发版不是 TODO 项，它是 changelog。注意 `[TODO-CLEAN]` **拦不住它**：
  那行不以日期开头、157 字节也不超长——机械判据只覆盖两种最常见的形态，覆盖不了「什么算 TODO 项」这个语义。
  所以改写进 `ci-releases.md` 是靠改写入方，不是靠门禁兜底。
- **只改纪律不加门禁** — 纪律 3 已经写了三周没执行，证明没有门禁的纪律在这份文件上不成立。

## 后果

- 提交前多一个判断、少一次无意义的写：与 TODO 项无关的提交不再碰 TODO.md。
- `TODO.md` 从 82074 B 降到 24303 B〔2026-09-16 实测〕，每个涉及待办的提交回合读它的成本降约七成。
- 写「做了什么」的人要另开 `docs/progress-archive/YYYY-MM-progress-log.md`；写错地方立即被 `[TODO-CLEAN]` 拦。
- 600 字节的行上限对表格行是紧约束：一行装不下说明该行在堆证据，拆成「一句缺口 + 链接」。
- 事故与验证过程见 evolution-log.md 2026-09-16 条目。
