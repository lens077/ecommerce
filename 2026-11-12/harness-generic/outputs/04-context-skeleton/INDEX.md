# context/ — 知识库入口

本文件是**路由**，不是内容。分层的目的只有一个：让 agent 按需加载，而不是每次把全部知识塞进上下文。

| 层 | 目录 | 管什么 | 什么时候进 |
|---|---|---|---|
| 团队级 | `team/` | 跨项目的协作/设计/环境约束 | 动契约、跨仓改造、查环境 |
| 框架级 | `harness-framework/` | AI 协作机制本身（门禁、上下文工程、自纠偏） | 改 AGENTS.md 或门禁脚本前 |
| 决策 | `decisions/` | 已定的架构/流程决策与替代方案 | 改硬规则、门禁、真相源归属前 |
| 项目级 | `project/{{PROJECT_SLUG}}/` | 本仓架构、模块、踩坑 | 具体功能开发 |

## 三个约定

1. **逐篇清单只维护在各层自己的 `INDEX.md`**。在这里再列一遍文件就是两份索引，必然分叉——
   所以本文件不列文件。
2. **每行只写「管什么 / 何时读」**，不写结论。结论写进被链接的文件，否则读者不用点进去就以为自己懂了。
3. **每个新文件都必须被所属层 INDEX 链接**，否则门禁的 `[ORPHAN]` 检查会红。

## 新增一层的判据

只有当「某类知识有独立的加载时机、且会被 ≥3 个任务复用」时才加层。层数越多，路由本身越贵。
