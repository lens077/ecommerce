# 注册 QQ 机器人账号并开通沙箱环境

Status: ready-for-human

只有人能做：账号注册、开发者资质填写、沙箱群创建。agent 无法代办。

本单是整个方案的最小前置——**它只解锁 P0**，不涉及备案、认证与提审，那些在
[04-正式环境资质与前置裁决](./04-正式环境资质与前置裁决.md)。

## 为什么先做这一单

沙箱不受 IP 白名单限制（平台事实，见 [spec.md](../spec.md)「平台侧限制」），
因此 P0 的全部验收可以在沙箱完成，不必等备案与出口 IP 落实。
把沙箱与正式环境的前置条件拆成两单，是为了让 P0 能在外部阻塞项解决之前先跑起来。

## 范围

1. 在 <https://bot.q.qq.com/> 注册机器人账号，取得 AppID 与 AppSecret。
2. 开通群聊与单聊（C2C）场景。**不开通频道场景**（本方案非目标）。
3. 创建沙箱测试群，邀请团队成员。注意平台限制：沙箱群成员不得超过 20 人。
4. 把 AppID 与 AppSecret 写入 Config Center 的 dev 环境，键位遵循
   `.service-matrix.yaml` 的 `conventions.config_center_key`（`{service}/{env}/bootstrap.yaml`）。

## 硬性约束

**AppSecret 不得进入仓库**（AGENTS.md 硬规则 4）。仓库里只写主机名与端口，凭据字段留空。
Consul 只做注册发现，不存配置。

AppSecret 同时是 ed25519 签名密钥的派生种子，泄漏等于任何人都能伪造平台回调。
本方案当前推荐 Webhook 接入（见 [wiring.md](../wiring.md) §4），签名校验是必须项。

## 验收标准

1. AppID 与 AppSecret 已存在于 Config Center dev 环境，且仓库内搜不到任何一段凭据。
2. 沙箱群已建立，机器人已加入，成员数不超过 20。
3. 用 AppID + AppSecret 能成功调用 <https://bots.qq.com/app/getAppAccessToken> 取得 Access Token。
4. 群聊与单聊场景在管理端显示为已开通，频道场景未开通。

## 一并确认的信息

启动 [02](./02-qqbot-服务骨架与事件接入.md) 前需要知道：

- AppID 值（非机密，可写进 dev 配置）。
- 沙箱 API 地址确认为 `https://sandbox.api.sgroup.qq.com`。
- 当前可申请的 intents 权限范围。本方案 P0 需要 `GROUP_AND_C2C_EVENT`（`1<<25`）。
  **传了无权限的 intents 会直接断连**，因此必须在开工前确认这一项已获批。
