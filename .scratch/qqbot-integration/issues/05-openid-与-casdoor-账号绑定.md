# P1：openid 与 Casdoor 身份的绑定

Status: ready-for-agent
Blocked by: 03

把 QQ 侧的 `openid` 与平台的 Casdoor 身份关联起来。
这是所有「需要知道你是谁」的功能的地基——没有它，单聊里的 `/查订单` 无法定位到平台用户。

## 为什么必须有一次显式绑定动作

**`openid` 不是 QQ 号。** 它的三条性质各自否决了一种看起来更省事的做法：

| 性质 | 后果 |
|---|---|
| **per-bot 维度**：由「平台 × 机器人」共同确定 | 换一个机器人，同一个 QQ 用户拿到的是另一个 `openid`。绑定关系与具体 AppID 强耦合 |
| **不可反查 QQ 号**：平台不提供 `openid` → QQ 号的映射 | 无法用 QQ 号匹配平台已有账号，**不存在任何隐式识别路径** |
| **单聊与群是两个维度**：`user_openid` 用于单聊投递，`group_openid` 用于群投递 | 「在群里认识这个人」不等于「能在单聊里认出他」 |

第二条是关键：既然不能反查 QQ 号，就没有「用户一说话就知道他是谁」这条路。
用户**必须**主动完成一次绑定。这不是产品体验上的取舍，是平台标识模型决定的。

## 范围

1. 绑定：指令 `/绑定` → 一次性绑定码 → Web 端提交完成关联。
2. 解绑：指令 `/解绑`。
3. 未绑定用户触发需要身份的指令时，返回绑定引导且不泄露任何数据。
4. 主动发送许可状态维护：响应 `C2C_MSG_REJECT` / `GROUP_MSG_REJECT` 事件。

不含只读查询指令，那在 [06](./06-p1-只读查询指令.md)。

## 绑定流程

前置条件：用户已在 QQ 单聊内与机器人对话，因此存在有效的被动回复窗口（60 分钟）。

1. 用户发送 `/绑定`。
2. `qqbot` 生成一次性绑定码，与 `user_openid` 一起写入绑定会话表，设置有效期。
3. `qqbot` 以被动回复返回带绑定码的提示，引导用户在 Web 端登录后输入该码。
4. 用户在 Web 端完成 Casdoor 登录并提交绑定码。
5. 校验绑定码有效且未使用，写入绑定关系，作废绑定码。
6. `qqbot` 在下一次交互时告知绑定成功。

**为什么用绑定码而不是 OAuth 跳转**：OAuth 跳转需要回调域名先备案并报备进 URL 白名单
（见 [04](./04-正式环境资质与前置裁决.md)），而绑定码只需要用户已在使用的 Web 端。
备案完成后可以增加 OAuth 跳转作为更短的路径，两者并存（OAuth 回调地址上限 10 条，容量充足）。

## 硬性约束

**1. 绑定关系是领域真相，必须进 PostgreSQL，不得放 Dragonfly。**
`.service-matrix.yaml` 的 `externals.redis` 写明：业务服务只放可丢缓存，
不得承载锁、幂等键或领域真相。
绑定关系一旦丢失**无法重建**——既不能反查 QQ 号，也没有第二份来源可以对照。

**2. 绑定表必须显式存储 AppID。** `openid` 是 per-bot 维度的，
不带 AppID 的绑定表在换机器人时无法区分哪些记录已失效。

**3. `user_openid` 与 `group_openid` 分两列存储，不假设相等。**
群内发言者的用户标识与单聊 `user_openid` 是否为同一值尚未核实
（[spec.md](../spec.md) 开放问题里「群内发言者的用户标识与单聊 `user_openid` 是否为同一值」一条）。
核实前按两个独立维度实现。

**4. 绑定码是安全凭据。** 必须一次性且有有效期，否则会成为账号劫持入口。
「一次性」要靠一次原子的「校验并标记已使用」保证，同样放 PostgreSQL。

**5. 绑定关系不等于授权。** `openid` 映射到某个用户 ID 只说明「是谁」，不说明「能做什么」。
`qqbot` 自身不是身份来源，调用下游时必须走与 Web 端相同的授权判定路径，
**不得自行拼装可信身份头**。

本仓已有一处同类缺陷可以直接借鉴教训：网关 jwt 中间件命中免鉴权白名单时不剥离入站头，
而 `behavior/identity()` 又把 `x-md-global-user-id` 当可信源，攻击者带该头即可冒名
（`TODO.md` 全局 P0 第 14 项「免鉴权入口身份可伪造」）。**不要复制这个模式。**

**6. 日志不得输出完整 `openid` 与绑定关系。**
本仓的管道侧 PII 脱敏当前存在缺陷（`TODO.md` 全局 P0 第 13 项：Lua 不支持 `{n}` 量词，
等于空操作），因此必须在写日志前自行处理，不能依赖管道。

## 验收标准

1. 绑定码在有效期内只能使用一次；重复提交返回明确错误。
2. 绑定码过期后不可用。
3. 未绑定用户发送需要身份的指令时返回绑定引导，且不泄露任何用户数据。
4. 解绑后立即失效，回到未绑定状态。
5. 绑定表中每条记录都带 AppID；换 AppID 后旧记录可被识别为失效。
6. 收到 `C2C_MSG_REJECT` 后，该用户被标记为不可主动触达。
7. 日志中无完整 `openid`。
8. 服务重启、Dragonfly 不可用两种情况下，绑定关系均不丢失。
