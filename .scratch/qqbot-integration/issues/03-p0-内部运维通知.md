# P0：内部运维通知与只读指令

Status: ready-for-agent
Blocked by: 02

在团队 QQ 群内跑通「收指令 → 回消息」和「外部触发 → 主动推送」两条路径。
本单是**接入本身是否成立**的验证，不碰用户数据。

## 为什么 P0 是内部通知而不是购物入口

三条外部阻塞项在 P0 全部不适用：

- 不需要 ICP 备案（消息不带外链）。
- 不需要账号绑定（内部群成员不需要定位到平台用户）。
- 不依赖 `TODO.md` 登记的交易缺陷修复（不查订单）。

而沙箱不受 IP 白名单限制，因此 P0 可以在正式环境资质落实之前完整验收。
详见 [spec.md](../spec.md)「与本仓现状的三处硬碰撞」。

## 范围

1. 指令 `/帮助`：返回可用指令列表。
2. 指令 `/健康`：返回各服务健康状态摘要。**内部群限定**，不对外开放。
3. 接收外部通知源（部署结果、告警）并推送到指定群。
4. 被动回复窗口与次数的显式管理（见「硬性约束」）。

## 消息形态

**纯文本（`msg_type=0`），不带链接，不用 Markdown。**

- Markdown（`msg_type=2`）需单独申请模板权限，未获批时返回 `40034127`。
- 链接域名需先报备且需 ICP 备案，而 `.service-matrix.yaml` 记录 apikv.com 未在阿里云备案。

两项都是外部依赖，P0 不等它们。消息渲染层要把「形态」做成可配置，
不要把纯文本假设散落到各处字符串拼接里——P2 要切 Markdown 时不应重写渲染层。

## 硬性约束

**被动回复的时效必须在代码里显式表达，这是设计约束不是异常处理。**
群聊窗口 5 分钟、最多 5 次；单聊 60 分钟、每条消息最多 4 次。
超时后 `msg_id` 失效并返回 `40034128`。

任何异步处理都必须在窗口内完成。若可能超时，要在窗口耗尽前先回一条「处理中」
（占用一次回复次数），而不是让请求静默失败。

`/健康` 会调用下游服务，是本方案第一个可能触碰窗口上限的指令——
把它作为窗口管理机制的验证用例。

**通知触发入口必须鉴权。**
范围里「接收外部通知源并推送到指定群」一项要求部署与告警系统能触发推送，这需要一个入站端点。
**它不能免鉴权**——一个不需要凭据就能「向群发消息」的端点，等于把一个已认证的机器人
变成任何人都能用的转发器。按 [spec.md](../spec.md)「安全与合规 · 身份边界」，
本方案不新增免鉴权的网关入口。

注意它与 Webhook 回调是**两条不同的入站路径**，信任模型相反，不要合并到一个端点：
Webhook 来自腾讯服务端、带不了我们的凭据、靠 ed25519 签名自证；
通知触发来自我们自己的内部系统、应当带凭据并过网关。
这也是 `gateway_prefix` 的一个真实用途，接线见 [wiring.md](../wiring.md) §3.2。

**日配额计数必须原子递增，不能读-改-写。**
Webhook 模式下本服务是多副本的（无状态、需满足 suite-wide `maxSkew=1` 打散）。
两个副本同时推送时，各自读到同一个旧值再各自写回，会**实际发 2 条、账上只加 1**，
已用量被算少进而超发。

这与存储选型无关——放 PostgreSQL 一样会发生，决定因素是写法。
用一次原子写完成：`INSERT ... ON CONFLICT (scope, openid, quota_date) DO UPDATE SET n = n + 1`；
放 Dragonfly 的短窗口计数同理，用 `INCR` 而不是 `GET` 后 `SET`。
判据与四类落点见 [spec.md](../spec.md)「频率账本」。

## 验收标准

1. 沙箱群内 `@` 机器人后，`/帮助` 在 5 分钟窗口内返回结果，
   且回复携带正确的 `msg_id` 与递增 `msg_seq`。
2. `/健康` 返回各服务状态；下游超时的情况下仍在窗口内给出可读回复，不静默失败。
3. 主动推送一条告警到群，返回成功；连续推送时不出现 `40034100`（频控）。
4. 通知触发端点在无凭据时拒绝请求，不会向群发出任何消息。
5. **多副本并发推送时日配额计数准确**：起 2 个副本并发推送 N 条，
   数据库里的计数等于 N，不小于 N。这一条要有专门的并发测试，不是手工点一次。
6. 服务重启后，同一事件不会被重复响应。
7. 被动回复次数达到上限时按预期降级，并记录 `40034128`，不产生重试风暴。
8. `scripts/verify-quick.sh` 通过。

## 退出条件

上述验收标准全绿，且连续运行 7 天无非预期断连。
满足后 P0 阶段结束，[05](./05-openid-与-casdoor-账号绑定.md) 解除阻塞。

**同 [02](./02-qqbot-服务骨架与事件接入.md)：本单也在沙箱验收，不覆盖正式环境连通性。**
「主动推送告警到群」一条在沙箱不受 IP 白名单约束，在正式环境则必须先完成
[04](./04-正式环境资质与前置裁决.md)。P0 退出**不等于**可以对外宣称机器人已上线。
