# 正式环境资质与四项前置裁决

Status: ready-for-human

只有人能做：域名备案、开发者认证、机器人提审、IP 白名单登记。agent 无法代办，
其中备案还有外部审批周期。

本单解锁**正式环境**。P0 在沙箱完成，不受本单阻塞。

## 四项裁决

这四项决定方案是否成立，不是实现细节。任一项没有结论，
[07](./07-p2-领域事件消费与主动通知.md) 就不能开工。

### 一、备案主体与域名

平台要求机器人下发消息里的链接域名先报备且需 ICP 备案。
`.service-matrix.yaml` 在 `externals.minio` 明确记录：apikv.com 未在阿里云备案，
域名直连必被 ICP 拦截。gorse、minio 均在该域名下。

结果：商品图片、订单详情页、支付页的链接**目前没有一个可用域名**。

需要决定：是否为本方案准备可备案域名，备案主体是谁，预计周期多久。
若结论是不备案，P2 的带链接通知不成立，方案止于 P1 的纯文本查询。

消息 URL 白名单上限 20 条，每年可改 50 次——是稀缺资源，域名规划要一次想清楚。

### 二、公网出口 IP

新机器人默认启用 IP 白名单，只有白名单内的公网 IP 能连 WebSocket 和调用 OpenAPI。
只作用于正式环境，沙箱不受限。

`.service-matrix.yaml` 记录：Kubernetes 节点是 `192.168.3.101-103`（内网）；
node1 是 `node1`，承载 Pangolin；node2 是 `node2`（阿里云，与集群无关）。

**这一项比初看更严重。** [wiring.md](../wiring.md) §4.2 的调查结论是：
本仓**没有任何真相源记载 k8s 集群的公网出口 IP，且拓扑强烈提示它不固定**——
`192.168.3.0/24` 是一个带 DHCP 的家用网段，出公网经路由器 NAT，
而集群拉镜像还依赖挂在开发机上的代理。

同时要纠正一个容易乐观的判断：**这个问题不因选 Webhook 而消失。**
白名单同时管「连 WebSocket」和「调 OpenAPI」，而发消息必然要调 OpenAPI。
入站可以走 Pangolin，出站不行。

需要决定：用哪个固定公网出口。wiring.md §10.3 给了三条候选
（应用层正向代理 / Cilium Egress Gateway / 整体落 node2），并说明
**nodeSelector 解决不了这个问题**——三个节点共用同一个出口。

> **本仓已经踩过同一个坑。** 企业微信告警接入的待办写明：必须配「企业可信 IP」，
> 不配则 API 报 `not allow to access from your ip`，**且该错误只在日志里，界面无感知**
> （[`docs/todo/统一可观测性体系.md`](../../../docs/todo/统一可观测性体系.md)）。
> qqbot 会以完全一样的方式失败。把「白名单未配置」列进排查清单第一条。

### 三、认证类型

三档配额差别直接决定 P2 的通知覆盖率上限：

| 认证类型 | 单聊 | 群 |
|---|---|---|
| 企业认证 / 个人认证 | 10 QPS | 60 条/分钟 |
| 未认证 | 5 QPS 且 30 条/分钟 | 30 条/分钟 |

单关系维度 20 条/分钟、每日 1000 条/用户与 1000 条/群的上限不随认证类型变化。

**注意一个容易被忽略的代价**：`openid` 是 per-bot 维度的标识。
如果先用未认证机器人上线、以后再换一个企业认证的 AppID，
**全部已绑定用户的绑定关系会作废，需要重做一次绑定**。
认证类型最好在有用户绑定之前定下来。见 [spec.md](../spec.md)「`openid` 的性质」。

### 四、谁做提审与持续运营

上线需提审。基本信息每月限改 5 次，指令面板上限 24 条，快捷菜单上限 12 条。
这是持续的人工事项，不是一次性配置。

需要决定：谁负责提审材料、谁负责后续的指令面板维护。

## 一并办理的申请

- **Markdown 模板权限**：未获批时 `msg_type=2` 返回 `40034127`。
  申请周期未知，属 [spec.md](../spec.md) 开放问题里「Markdown 模板权限的申请周期」一条。
- **intents 权限**：本方案需要 `GROUP_AND_C2C_EVENT`（`1<<25`）；
  按钮功能需 `INTERACTION`（`1<<26`）；主动消息审核结果需 `MESSAGE_AUDIT`（`1<<27`）。
  传了无权限的 intents 会直接断连，因此权限批准情况要逐项确认，不要一次全填。

## 验收标准

1. 四项裁决各有明确书面结论，写入本单的 `## Comments`。
2. 若结论为「做」：域名完成 ICP 备案并报备进消息 URL 白名单；
   固定公网出口 IP 已实测确认并加入平台 IP 白名单；认证类型已完成；机器人已过审上线。
3. 正式环境下能成功接收事件并调用 OpenAPI 发出一条消息（验证白名单确实生效）。
   **这一项必须实际发一条消息**——只验证入站不能证明出站白名单已生效。
