# 地址簿页拆分与写操作反馈

Status: ready-for-agent

依赖：02。可与 04 并行。

## 问题

`frontend/apps/consumer/src/routes/profile/addresses/index.tsx` 的 `RouteComponent` 约 450 行，一个组件里同时管：列表渲染、编辑/新增对话框、定位权限对话框、两个 Backdrop、7 个 `useState`。具体缺陷：

1. **保存失败不可见、输入丢失**：`handleSaveAddress` 调用 `createAddress`/`updateAddress`（`useAddresses` 暴露的是 `mutate`，不返回 Promise）后立即 `setOpenDialog(false)`。请求失败时对话框已经关了，用户什么也看不到。
2. **加载态混用**：保存按钮与 Backdrop 用的是列表查询的 `isLoading`，与写操作无关；`useAddresses` 已暴露 `isCreating`/`isUpdating`/`isDeleting` 却没被用。
3. **删除无确认**：点删除图标直接 `deleteAddress`。
4. **关闭按钮无无障碍名称**：两个对话框标题栏的关闭 `IconButton` 没有 `aria-label`。
5. **登录守卫重复**：`beforeLoad` 里「`fetchIdentity` → 未登录提示 → `context.auth.login()`」与 `routes/profile/index.tsx` 逐行相同（Repowise 报的 29% 重复主要来自这里），只是 i18n key 不同。
6. `handleLocationPermissionConfirm` 失败时只 `console.error`，用户不知道定位失败，也没有退回手填的提示。

## 实现步骤

1. `hooks/useAddresses.ts`：新增返回 Promise 的写方法（例如 `createAddressAsync`/`updateAddressAsync`，内部用 `mutateAsync`），或把现有方法直接改为 `mutateAsync`；同步修改所有调用方（本页与结算页），保持 `onSuccess: invalidateList` 不变。
2. 保存流程：`await` 写操作；成功后关闭对话框；失败时保持对话框打开、保留表单，并在对话框内显示 `toAppError(err).message`（consumer 约定，不要写 `String(err)`）。
3. 按钮与遮罩的忙碌状态改用 `isCreating || isUpdating`（保存）与 `isDeleting`（删除），列表的 `isLoading` 只用于列表区域。
4. 删除加确认：使用 MUI `Dialog`；确认按钮用危险色，沿用本页现有配色，不新增颜色。
5. 两个关闭 `IconButton` 加 `aria-label={t("common:action.close")}`（key 不存在就在 `@ecommerce/i18n` 的 common 命名空间补上中英文）。
6. 拆分组件，放在同目录或 `src/components/address/`：
   - `AddressList`（列表 + 空态 + 加载态）；
   - `AddressEditDialog`（内部用 02 的 `AddressForm`）；
   - `LocationPermissionDialog`（定位权限；失败时通过 `addNotification` 提示「定位失败，请手动填写」，再打开编辑对话框）。
   `RouteComponent` 只负责组装与状态编排。
7. 抽出路由守卫：新建 `src/lib/requireLogin.ts`，导出 `requireLogin(messageKey: string)`，返回可直接赋给 `beforeLoad` 的函数；`profile/index.tsx` 与 `profile/addresses/index.tsx` 都改用它，行为（先提示再登录）不变。
8. 回归测试：为「保存失败时对话框保持打开且显示错误」补一个组件测试（mock `AddressService.createAddress` 返回错误）。这是本单修的 bug 1，只补这一条。

## 验收标准

1. `profile/addresses/index.tsx` 中 `RouteComponent` 的函数体不超过 150 行（`awk '/^function RouteComponent/,/^}/' <file> | wc -l` ≤ 150）。
2. `grep -n "beforeLoad: async" frontend/apps/consumer/src/routes/profile/index.tsx frontend/apps/consumer/src/routes/profile/addresses/index.tsx` 无输出（两处都改用 `requireLogin`）。
3. 回归测试「保存失败对话框保持打开」存在且通过（测试名写进完成自检）。
4. `grep -c 'aria-label' <拆出的对话框文件>` 每个对话框文件至少 1。
5. `cd frontend && pnpm ready` 退出码 0；`pnpm test -- src/a11y` 中 `/profile/addresses（登录态）恰好一个 h1 且层级不跳级` 仍通过。

## 不做

- 不做视觉迁移（`lantern` 令牌），不改现有配色与布局观感。
- 不接 `setDefaultAddress`（现在通过编辑表单的 `isDefault` 设置默认，行为保持）。
