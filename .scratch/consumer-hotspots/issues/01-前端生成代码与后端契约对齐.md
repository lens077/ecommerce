# 前端生成代码与后端契约对齐

Status: ready-for-agent

依赖：无。02–04 依赖本单（它们要在正确的类型上改地址写入）。

## 问题

前端使用的 protobuf-es 生成代码是两份手工快照，后端契约改了它们不会跟着变：

| 快照 | 最后更新 | 与 `backend/api/**/*_pb.ts` 的差异（2026-09-24） |
|---|---|---|
| `frontend/apps/consumer/src/gen/api/`（10 个 `*_pb.ts`） | `f88ee818` 2026-08-07 | **address**：`CreateAddressRequest` 仍有 `userId`（后端 `82a1883e` 已 reserved）；**cart**：`spu_id`/`sku_id`/`cart_item_id` 为 `uint64`，后端为 `int64`；其余 8 份只差生成器版本头与 descriptor 选项 |
| `frontend/apps/consumer-next/src/gen/api/`（product、search） | — | 仅版本头与 descriptor 差异，无字段差异 |

后果：`hooks/useAddresses.ts` 的 `createAddress` 仍在请求里带 `userId: userStore.getState().account.id`。服务端按设计从网关认证元数据取用户（`82a1883e fix(api): bind address ownership`），前端这个字段要么被丢弃、要么在 JSON 编码下引发未知字段问题；无论哪种，前端类型都在对一个已经不存在的契约编程，TypeScript 也拦不住。

后端生成物由 `cd backend && make api` 产出（`backend/buf.gen.ts.yaml`，`out: .`，写到 `backend/api/<pkg>/v1/*_pb.ts`；需要先在 `frontend/` 执行过 `pnpm install`，Makefile 从 `frontend/node_modules/.bin` 取 `protoc-gen-es`）。仓库里没有把它同步进前端 `src/gen` 的脚本。

## 实现步骤

1. `cd backend && make api`，确认 `backend/api/**/*_pb.ts` 是最新的（应无 diff；有 diff 说明后端也漂了，一并提交）。
2. 确定同步方式并落地，二选一，写进提交说明：
   - **A（推荐，改动小）**：新增 `scripts/sync-ts-gen.sh`，把 `backend/api/<pkg>/v1/*_pb.ts` 复制到两个前端的 `src/gen/api/<pkg>/v1/`，只复制该应用已有的包（consumer 10 个，consumer-next 2 个）；带 `--check` 模式，逐文件比对，不一致时打印文件名并以非零退出。
   - **B**：让前端直接引用 `backend/api` 的生成物（路径别名或 workspace 包），删除两份快照。改动面更大（Vite/Next 构建、`tsconfig` 路径、Docker 构建上下文都要核对），只有 A 不可行时才用。
3. 执行同步，更新两份快照。
4. 删除 `hooks/useAddresses.ts` 里 `createAddress` 的 `userId` 字段；该文件对 `userStore` 的 import 若随之无用，一并删除。
5. `cart_pb.ts` 的 `uint64 → int64`：protobuf-es 里两者在 TS 侧都是 `bigint`，按类型检查结果处理；`pnpm ready` 的类型检查报错的地方逐个修，不做语义变更。
6. 把 `sync-ts-gen.sh --check`（或 B 方案下的等价检查）接进 `scripts/verify-quick.sh` 的前端段，让以后后端改 proto 而没同步前端时门禁变红。按 AGENTS.md 硬规则 5，在接线处写一句触发它的事故：「2026-09-24 发现 consumer 快照停在 08-07，`CreateAddressRequest` 仍发送已 reserved 的 `user_id`」。

## 验收标准

1. `scripts/sync-ts-gen.sh --check` 退出码 0；手工在任一快照文件末尾加一行注释后退出码非 0 且打印该文件名（验证后还原）。
2. `grep -rn "userId" frontend/apps/consumer/src/hooks/useAddresses.ts` 无输出。
3. `grep -n "user_id = 3" frontend/apps/consumer/src/gen/api/address/v1/address_pb.ts` 无输出。
4. `cd frontend && pnpm ready` 退出码 0。
5. `scripts/verify-quick.sh` 的前端段包含上述 `--check` 且为绿。

## 不做

- 不改 proto，不改后端逻辑。
- 不升级 protoc-gen-es 版本（沿用 `frontend/` 锁定的版本）。
