# 前端生成代码与后端契约对齐

Status: done

## 问题与实现

consumer 的 CreateAddressRequest 快照仍含后端已 reserved 的 user_id，类型检查无法发现契约漂移。本单保持 proto 不变，以 `backend/Makefile` 的 `make api` 生成物为来源。

`scripts/sync-ts-gen.sh` 调用 Python 实现：固定应用包清单、递归相对生成依赖（包括 third_party）、统一 EOF 为一个换行、保留手写入口。`--check` 只读，报告缺失、内容漂移和过期生成物；正常同步重跑无 diff。创建地址不再发送 userId。检查与隔离副本回归接入 `verify-quick.sh` 前端链，接线注释记录触发事故。

## 验收标准

1. `scripts/sync-ts-gen.sh --check` rc=0；`python3 scripts/test-sync-ts-gen.py` rc=0，覆盖依赖漂移、只读、缺失、过期及手写文件保护。
2. `useAddresses.ts` 不再发送 userId，consumer 生成的 CreateAddressRequest 不再有该字段。
3. `cd frontend && pnpm ready` rc=0，`scripts/verify-quick.sh` 前端链 rc=0。
