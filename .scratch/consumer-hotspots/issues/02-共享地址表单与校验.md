# 共享地址表单与校验

Status: ready-for-agent

依赖：01。03、04 依赖本单。

## 问题

地址表单写了两份，已经分叉并造成回归：

| 位置 | 省市区输入 | 区县必填 | 空表单字面量 |
|---|---|---|---|
| `routes/profile/addresses/index.tsx`（`RouteComponent` 内的对话框） | `components/address/RegionSelect.tsx` | 由 `onDistrictRequiredChange` 决定（正确） | 在 `handleOpenDialog` 里写了一遍 `useState` 初值、又写了一遍 |
| `routes/checkout/index.tsx`（`AddressPickerDialog`） | 三个自由文本 `TextField` | **恒为必填**（错误） | `emptyAddressForm` 常量 |

`backend/api/address/v1/address.proto` 的 `AddressDetail.district` 允许为空，理由写在字段注释里：49 个省直辖县级行政区（琼海、仙桃、石河子等）本身就是末级。结算页强制必填，这些地区的用户在结算时新增不了地址；自由文本还会写入与 `RegionSelect` 规范名不一致的省市名。

## 实现步骤

1. 新建 `src/components/address/AddressForm.tsx`（或 `src/features/address/`，与仓内既有组织方式一致即可）：
   - 受控组件：`value: AddressFormData`、`onChange`、`error?: string | null`、`dense?: boolean`（结算页弹窗用 `size="small"` 与更紧凑的间距，地址簿页用默认尺寸）。
   - 字段：收件人、电话、`RegionSelect`、详细地址、设为默认。省市区**只能**通过 `RegionSelect` 输入。
   - 内部维护 `districtRequired`（来自 `RegionSelect.onDistrictRequiredChange`），通过回调或导出的校验函数交给调用方。
2. 同目录新建纯函数 `validateAddressForm(data, { districtRequired }): string | null`（返回 i18n key 或 `null`），规则与 proto 一致：
   - `recipientName` 1–255、`recipientPhone` 1–50、`province`/`city` 1–64、`detail` 1–500 字符；
   - `district`：`districtRequired` 为真时 1–64，否则 0–64。
   - 两个调用方都只用这一个函数，删除各自的内联 `if (!a || !b ...)`。
3. 导出 `EMPTY_ADDRESS_FORM`（冻结对象），删除两处重复的空表单字面量。
4. i18n：两页当前用的是两套 key（`addresses.form.*` 与 `checkout.address.*`）。表单组件统一用一套（建议 `addresses.form.*`），另一套中不再使用的 key 从 `@ecommerce/i18n` 的资源里删除；`pnpm ready` 若有 i18n key 完整性检查，保持绿。
5. 回归测试：为 `validateAddressForm` 补一个测试文件，至少覆盖「`districtRequired=false` 时区县为空也通过」「`districtRequired=true` 时区县为空不通过」「超长 detail 不通过」。这是本单修复的 bug 的直接回归，不要扩展成字段排列组合的表驱动大表。

## 验收标准

1. `validateAddressForm` 的测试文件存在且通过，含上述三个用例（测试名自拟，写进完成自检）。
2. `grep -rn "recipientName ||\|!form.recipientName\|!formData.recipientName" frontend/apps/consumer/src/routes` 无输出——页面里不再有内联必填校验。
3. `grep -rn "label={t(\"checkout.address.province\")" frontend/apps/consumer/src` 无输出——结算页不再有自由文本省份输入。
4. `cd frontend && pnpm ready` 退出码 0；`pnpm test -- src/a11y` 绿（两个页面的标题层级断言不变）。

## 注意

- `Typography` 的 `variant` 决定标题标签（consumer 没有 ThemeProvider），表单里的说明文字要显式 `component="span"` 或 `"p"`；否则 a11y 测试会红，这正是 `a49fad74`、`821b2400` 修过的 bug。
- 新组件不要引入硬编码颜色；沿用调用方传入的样式或 `tokens`，不要混用 `lantern`（`DESIGN.md` 迁移清单）。
