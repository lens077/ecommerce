# 结算页地址选择与提交

Status: ready-for-agent

依赖：02（以及 03 步骤 1 对 `useAddresses` 的 Promise 化；两单并行时先合入的一方做，另一方复用）。

## 问题

`frontend/apps/consumer/src/routes/checkout/index.tsx`（689 行）：

1. **`AddressPickerDialog` 内嵌在页面文件里**（约 200 行），复制了一份地址表单（02 处理表单本身，本单处理弹窗）。
2. **交互元素嵌套**：每个地址项是 `<Box component="button" onClick=…>`，里面放 `<Radio>`（`input`），`Radio` 也不在 `RadioGroup` 中。button 里不能放交互内容，读屏会念出两个控件、键盘焦点行为不可预期。
3. **新增地址「发出即关」**：`handleCreate` 调 `createAddress(form)` 后立即 `resetForm()`；失败时输入丢失且无提示；成功后新地址也不会被选中，用户还要再点一次。
4. **静默丢弃商品**：`handleSubmit` 里
   ```ts
   CartItemIds: selectedItems.map((i) => i.cartItemId).filter((id) => /^\d+$/.test(id)).map((id) => BigInt(id))
   ```
   非数字 ID（本地临时购物车项，未同步到服务端）被悄悄过滤，订单会少商品而用户不知道。注释写的理由是「直接进 `BigInt()` 会抛错」——那是在掩盖问题，不是解决。
5. 关闭 `IconButton` 没有 `aria-label`。

## 实现步骤

1. 把 `AddressPickerDialog` 与 `addressFullText` 移到 `src/components/address/AddressPickerDialog.tsx`；新增表单部分改用 02 的 `AddressForm` 与 `validateAddressForm`。
2. 列表改为 MUI `RadioGroup` + `FormControlLabel`（`value=addressId`），整行可点通过 `FormControlLabel` 实现；删除 `component="button"` 的外层 Box。键盘上下键应能在地址间切换（`RadioGroup` 原生行为）。
3. 新增地址：`await` 创建（依赖 03 步骤 1 的 Promise 化写方法）。成功后用响应里的 `addressId` 调 `onSelect(addressId)`，并收起新增表单；失败时保留表单并在弹窗内显示 `toAppError(err).message`。
4. 静默丢弃改为显式阻断：
   - 在 `canSubmit` 的计算里加一项「所有选中商品的 `cartItemId` 都是服务端 ID」；不满足时禁用提交按钮，并在提交栏上方显示提示（新增 i18n key，例如 `checkout.unsyncedItems`：「购物车中有未同步的商品，请返回购物车刷新后再下单」）。
   - 本地临时 ID 的来源在 `src/store/cart.ts`，先读它确认生成规则；判断条件与生成规则对应，不要只写正则。
   - 背景：匿名购物的服务端访客购物车见 `docs/design/platform/anonymous-shopping.md`；购物车条目标识的迁移见 `TODO.md`「购物车条目标识」。本单只保证「不静默丢」，不改购物车同步逻辑。
5. 关闭按钮加 `aria-label`。
6. 回归测试：补一个测试覆盖 bug 4——选中商品含本地临时 ID 时提交按钮禁用且提示可见，`createOrder` 未被调用。只补这一条。
