库存预占

一个 ReserveGroup 的最小正确性清单
问题必须看到红旗
整组原子性一个 transaction 包住所有条目、流水和状态循环外没有事务，或部分写入直接用 pool
防超卖单条条件更新含 available >= quantity，检查影响行数先 SELECT 再普通 UPDATE，或忽略 0 行
锁顺序跨多 SKU 按统一键排序后锁定按请求顺序拿锁
幂等reservation_id 唯一，重放同 payload 返回首次结果只用订单号；重放再次扣库存
失败任一条失败，整组回滚；错误可重试性明确基础设施自动重试非幂等 Reserve

购物车数量

数量命令的接口与验证
层职责不应承担
serviceproto → 领域命令、身份提取、错误码映射决定数据库是否更新成功
biz数量范围、0 的语义、条目标识和用户归属规则导入 proto 或 pgx/sqlc 类型
data用认证用户 + cart_item_id 条件更新，返回命中结果把 0 行当成功
transaction更新与返回统计属于同一一致性读取把后续查询当成更新成功证明

测试分层

  • biz：fake Repo 测数量、0、错误语义。
  • data：真实 PostgreSQL 测 SQL、owner 条件、唯一约束、事务回滚。
  • 并发：至少两事务竞争同一 SKU，证明不会超卖；多 SKU 按同一顺序锁定。
  • 前端：外部 store 快照测试一次替换、一次通知、选择持久化。
项目约束：后端测试不要使用 go-sqlmock 或 pgxmock；数据库语义用真实 PostgreSQL。具体规则见 go-testing.md。
