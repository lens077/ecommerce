# 消费者首页 UX 设计评审

## Design Health Score

**18/36（50%，Acceptable）**。视觉系统已经形成鲜明、难以替换的「灯市」世界，但真实商城行为、移动端关键入口和失败恢复还没有达到可发布水平。

## Design-Specificity Verdict

**视觉高度 authored，商城行为却还没有同等程度地为真实 B2B2C 场景定制。**

纸、竹、墨、朱砂、宋体、拱顶灯卡和次第点灯共同构成了强烈 own-world；即使去掉文字，页面仍可被识别为「灯市」，明显高于常见电商模板。不过它目前更像精致的生活方式选物集，而不是多商家综合商城：商家差异、比较依据、履约信心、库存真实性都很弱。视觉隐喻已经不可替换，交易行为却仍可被任意精品店复用。

Detector 对目标 JSX 返回 `[]`。这证明目标没有命中工具可识别的常见视觉反模式，不代表体验无问题；最高优先级缺陷集中在跨组件交互、断链路、响应式布局和错误语义，静态视觉规则不会捕获它们。

## What Works

1. **材料系统真正成立。** 暖纸、竹线、炭墨、稀缺朱砂和灯内发光被一致地用于 hero、类目架、卡片、AppBar 与 Footer，不是给默认商城套一层主题色。
2. **叙事层级清楚。** 桌面 55/45 hero、唯一主 CTA、类目桥和商品灯阵形成自然路径；移动端仍保留同一叙事，而不是退化成普通卡片堆叠。
3. **可访问性基础有意识。** 标题与 nav 语义、真实链接、插画标签、等宽价格数字、focus-visible 和 reduced-motion fallback 都已经存在，后续修复有可靠底座。

## Priority Issues

### P1 — 隐私 gate 破坏真实首印象，并在移动端溢出

每个首次访问者都会先看到它。灰色遮罩压灭灯光，白底蓝按钮进入另一套视觉语言，同时暴露 3 个勾选项、关闭、全部拒绝、保存设置、全部接受共 7 个选择；390px 证据中最右侧动作被截断。

**Fix:** 改成响应式 sheet/dialog。第一层只保留「拒绝可选项」和「接受可选项」，细分设置放进次级入口；移动端堆叠或换行，触控目标至少 44px，并用纸、墨、朱砂语法重做。关闭要么被移除，要么明确且持久化为一个选择。

### P1 — 首页展示可操作库存，但下游路由不支持这个承诺

8 个类目全部进入同一个无参数路由，该路由只渲染 `cart`；`DEMO-*` 商品又进入真实 API 详情页。视觉上最强的 affordance 恰好最容易背叛用户预期。

**Fix:** 只保留一种诚实模式：要么把演示库存做成不可交易的独立 showroom，并明确标注；要么提供完整的演示详情闭环。类目必须携带 key 进入可工作的类目或筛选结果。不可用的 Footer 项不要伪装成链接。

### P1 — 未登录移动端没有稳定可见的购物车，头部动作疑似被搜索框挤出

购物车是电商的基础入口，却只出现在已登录移动菜单分支；归档移动截图仅看见品牌与搜索，也与窄屏头部被挤压的源码风险一致。

**Fix:** 不论登录状态都保持购物车可见。窄屏改为双行 header，或让搜索收敛为可展开入口，使品牌、搜索、购物车、账号在 390px 内都能稳定出现。

### P2 — 商品灯阵很美，但不足以支持购买比较

12 个商品只有名称、虚构商家和起价，作为画廊足够，作为综合商城决策信息不足；统一线稿还让不同类目的商品显得过于相似。

**Fix:** 在真实数据允许范围内补 1–2 个决策信号，例如规格摘要、可售状态、履约信息或商家上下文。首页先收敛成更小的编辑精选，并给出明确的完整货架入口；服务接通后以真实商品图替换演示线稿。

### P2 — 键盘语义与失败恢复落后于视觉完成度

Logo、搜索图标和搜索结果卡存在 click-only `Box`/`div`；搜索结果不能可靠地由键盘逐项进入，网络失败又被当作正常空结果。

**Fix:** 所有交互对象使用 link/button 语义，补本地化可访问名称与明确焦点环；搜索失败显示可理解的原因和「重试」，不要与零结果复用同一文案。

## Cognitive Load

**回访用户：中等，8 项检查失败 2 项。首次用户：高，受 consent gate 影响失败 5 项。**

- `Pass` 分组、视觉层级、工作记忆：hero、类目和灯阵边界明确；商品名、商家、价格都保持可见。
- `Fail` chunking：8 个类目与 12 个等权商品缺少语义分组。
- `Fail` minimal choices：类目 8 项、商品 12 项都超过单个决策点的 4 项工作记忆阈值。
- `Fail on first visit` single focus / one thing at a time / progressive disclosure：隐私管理抢走购物任务，7 个并列选择一次性暴露。

类目和商品数量本身符合电商常态；真正的问题是缺少分组、筛选或足够的比较信号来抵消选择数量。

## Emotional Journey

- **Arrival:** 目标情绪是温暖、从容的好奇；暖纸、醒目的标题和单一朱砂动作能做到这一点。
- **First-visit valley:** 隐私弹窗立刻用通用 MUI 世界覆盖全部 authored 体验，移动端动作截断又加入「页面可能坏了」的不安。
- **Peak:** 主灯与入视点灯序列有记忆点，桌面构图让品牌叙事与主推商品互不抢夺。
- **Browsing valley:** 页面承诺一条活着的市场长街，商品却因统一插画和稀薄信息变成同质化展品；类目和详情断链进一步打破信任。
- **Ending:** 演示披露很诚实，但以内部名词「ListProduct」收尾，不是购物者下一步；占位 Footer 又削弱了帮助与隐私承诺。

## Persona Red Flags

**Casey（分心的移动购物者）:** 单手打开页面先遇到长设置弹窗，三个动作挤在一行且「接受所有」被截断；关闭后未登录状态看不到购物车，横向类目又隐藏滚动条，没有「后面还有内容」的线索。

**Jordan（首次购物者）:** 「看灯去」更像编辑内容而不是「查看商品」；小号「演示商品」只放在灯阵标题旁，hero 和卡片仍像真实库存。点击类目看到 `cart`、点击商品可能得到后端加载失败，页面没有解释这种跳变。

**Riley（边界测试者）:** 关闭隐私弹窗后没有任何选择被保存；文案承诺 Footer 可修改设置，Footer 却没有真实入口。搜索网络失败也无法与真正零结果区分。

## Minor Observations

- JS `scrollIntoView({ behavior: "smooth" })` 仍可能在 reduced-motion 用户下播放；CSS media query 不一定能覆盖显式 JS 行为。
- 移动类目隐藏 scrollbar，使横向继续浏览不可发现。
- 「食百」有品牌味，但不如「食品百货」让首次用户一眼理解。
- 演示说明向购物者泄露内部 RPC 名称「ListProduct」。
- Hero 的整卡 link 内又放了一个按钮外观的 `span`，视觉上像两个动作，实际却进入同一路径。
- stock MUI 搜索、购物车、账号图标与 authored 的印章和墨线语言相比明显偏通用，但优先级低于功能缺口。

## Questions to Consider

1. 「灯市」只是视觉包装，还是 B2B2C 机制也能成为隐喻的一部分——不同商家摊位、可信服务信号、真正可走通的市集路径？
2. 演示库存究竟是独立 showroom，还是必须走真实购买流？当前中间态同时承诺两者，却没有完成任何一个。
3. 用户选商品时，名称和价格之后最重要的一个真实信号是什么：商家信任、履约、规格还是库存？
4. 隐私选择能否遵守首页「一个决定性的朱砂印」纪律，把详细设置渐进披露？
